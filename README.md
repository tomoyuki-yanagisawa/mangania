<h1 align="center">MangaNia</h1>

<p align="center">
  自炊した漫画画像などの ZIP / 画像フォルダを表示する、小さなネイティブビューアの試作です。<br>
  Windows 7 を優先しつつ、macOS / Linux でもビルドできる構成にしています。
</p>

<p align="center">
  <a href="docs/DESIGN.md">設計</a> ・ <a href="docs/DECISIONS.md">技術判断</a> ・ <a href="docs/PREFERENCES.md">既定値・UX</a>
</p>

## 使い方

```sh
cargo run --release -- path/to/book.zip
cargo run --release -- path/to/image-folder
# 先読み数を指定する場合（config.toml の prefetch を上書き。単ページ表示はページ数、見開き・混合表示は2ページ単位）
cargo run --release -- --prefetch 4 path/to/book.zip
```

引数なしで起動した場合は空のウィンドウが開きます。ZIP または画像フォルダをウィンドウへドラッグ＆ドロップすると読み込みます。画像フォルダは選択したフォルダ直下の画像だけを読みます。サブフォルダを読むときは、そのフォルダを開き直してください。

GUIを開かずに確認することもできます。

```sh
# ページ一覧（自然順）を表示
cargo run --release -- --list path/to/book.zip

# 全ページをデコードしてエラーを確認（失敗時は終了コード1）
cargo run --release -- --check path/to/book.zip

# 指定ページを画像として出力（1始まり）
cargo run --release -- --render-page 1 out.png path/to/book.zip
```

Windows の exe は GUI サブシステムでビルドしているため、ダブルクリックではコンソールウィンドウが開きません。`--list` などの CLI モードでは親コンソールに接続し、標準出力のリダイレクトも維持します。ウィンドウのタイトルバーとタスクバーには、`assets/icon.svg` からビルド時に生成したアプリアイコンを表示します（Windows のみ）。

| 操作 | キー・マウス |
| --- | --- |
| 次のページ | Right / 左クリック / ホイール下 |
| 前のページ | Left / 右クリック / ホイール上 |
| 見開き・混合表示中に1ページ進む | 中クリック |
| 先頭 / 末尾 | Home / End |
| 表示モードの切替（単ページ → 見開き → 混合） | メニューの「表示」、または V |
| 縮小フィルタの切替 | メニューの「表示」>「縮小フィルタ」（Windows / macOS） |
| 小さい画像の拡大を許可 | メニューの「表示」>「拡大を許可」（Windows / macOS） |
| 全画面の切替 | メニューの「表示」>「全画面表示」、または F11 / Enter |
| 表示中のページを保存 | メニューの「ファイル」>「表示中のページを保存」、Ctrl+S / Cmd+S、または左ダブルクリック |
| 終了 | Esc（全画面中は全画面解除。ウィンドウ表示中は終了） |

マウスはウィンドウ内の任意の位置で操作できます。ホイールはトラックパッドの小さなスクロールを既定で約50px分ためて1ページ送りにします（`mouse.toml` で変更可能）。見開き・混合表示時の左右クリック・ホイールは表示単位で進みますが、中クリックだけは常に1ページ単位で進みます。キーとマウスの割り当ては設定ファイルで変更できます。左ダブルクリックに保存を割り当てているため、左シングルクリック（次のページ）はダブルクリック判定のため約500ms待ってから実行されます。ウィンドウが非アクティブなときのクリックは操作に使いません（Windows では OS のアクティブ化クリックを破棄します）。

メニューからも同じ操作ができます。

- **ファイル**: 表示中のページを保存 / キャッシュを削除
- **移動**: 次のページ / 前のページ / 1ページ進む / 1ページ戻る / 先頭へ / 末尾へ
- **表示**: 単ページ表示 / 見開き表示 / 混合表示 / 縮小フィルタ / 拡大を許可 / 全画面表示

## 想定用途

ローカルにある画像を自分で見るためのビューアです。次のようなファイルを想定しています。

- 自分でスキャンした漫画画像（自炊）
- 購入先や配布元が許可している電子書籍・画像
- 開発やテスト用の合成画像

本アプリは画像ビューアであり、漫画などのコンテンツを同梱・配布しません。利用するファイルは、自炊など適法に入手・作成したものに限ってください。

## 表示モード

- **単ページ表示**: 1ページずつウィンドウ全体に表示します。既定です。
- **見開き表示**: 現在ページを右、次ページを左に並べます（右→左）。ページ送りは2ページ単位です。
- **混合表示**: ページの向きで単ページと見開きを切り替えます。
  - 横長（正方形を含む）のページは、ウィンドウ全体に単ページ表示します。
  - 縦長のページは右半分のセルに表示します。次ページも縦長なら左セルに並べ、それ以外なら左セルは空白になります。
- メニューの「表示」または `V` で **単ページ表示 → 見開き表示 → 混合表示** の順に切り替えられます。
- 選んだ表示モードは `config.toml` に保存され、次回起動時に復元されます。
- ページがないセルは背景色のまま空白になります。見開き表示で末尾に1ページだけ残る場合や、混合表示で縦長ページの次が横長・末尾の場合が該当します。
- 見開き表示中の中クリックでは、開始ページを1つ進めます（例: `(1,2)` → `(2,3)`）。その後も2ページ単位の送りは同じ偶奇を保ちます。
- 見開き表示の組は先頭から `(1,2)`, `(3,4)`, ... です。混合表示ではページの向きに応じて組が変わり、表紙を単独表示する設定は未実装です。
- ネイティブメニューは Windows / macOS のみです。Linux では既定で `V` キーで切り替えます。

単ページはウィンドウ全体に、見開きと混合表示の縦長ページは左右半分のセルにフィットします。混合表示の表示サイズはページ自身の向きだけで決まるため、隣のページとの組み合わせが変わっても再縮小しません。

## 拡大と縮小

画面より大きいページは、縦横比を保ったまま縮小して画面に収めます。画面より小さいページは、既定では画面いっぱいまで拡大します。

小さい画像を拡大したくないときは、メニューの「表示」>「拡大を許可」のチェックを外すか、`config.toml` で `allow_upscale = false` にしてください。この場合は縮小だけを行い、画像は原寸のまま中央に表示します。設定はチェック状態で表示され、変更すると `config.toml` に保存されます。Linux ではネイティブメニューがないため、`config.toml` を直接編集してください。

## 縮小フィルタ

画面サイズに合わせて画像を縮小するときのアルゴリズムを選べます。既定は `triangle` です。

- **Nearest**: 最も速いが、ブロック状のジャギーが出やすい。
- **Triangle**: 既定。速度と画質のバランスが良く、自炊画像では無難。
- **Hamming**: Triangle と同じくらい速く、輪郭が締まる。縮小向き。
- **Catmull-Rom**: Triangle より輪郭が締まる。細かい線が強調される一方、過剰なシャープ感が出ることがある。
- **Mitchell**: Catmull-Rom と同じくらいの速度で、より軟らかい。リンギングを抑えたいとき。
- **Gaussian**: なめらかで軟らかい。細部はややぼける。
- **Lanczos3**: 最もシャープ。スクリーントーンがくっきりする一方、リンギングやモアレが出やすく、縮小に時間がかかる。

Windows / macOS ではメニューの「表示」>「縮小フィルタ」から切り替えられます。選択は `config.toml` に保存されます。Linux ではネイティブメニューがないため、`config.toml` の `scale_filter` を直接編集してください。

縮小結果はページごとに1枚だけ表示サイズの画像としてメモリにキャッシュされ、同じページの再描画や近いページの移動で再利用されます。表示サイズは単ページならウィンドウ全体、縦長ページなら左右半分のセルです。混合表示でもページの向きだけで決まり、描画時の再縮小は行いません。原寸のデコード結果は保持しません。キャッシュは上限付きで、現在ページから遠いページの画像から破棄されます。ウィンドウサイズ、縮小フィルタ、表示モード、拡大の可否を変更したときはキャッシュを捨てて再デコードしますが、ページ移動では破棄しません。

## ディスクキャッシュ

ZIP 内の画像エントリは、専用のディスクキャッシュへ展開してからデコードします。展開済みバイト列をメモリに保持せず、キャッシュファイルを直接 `image::ImageReader` で読みます。画像フォルダはキャッシュを使わず、元の画像ファイルを直接読みます。

- キャッシュ先:
  - Windows: `%LOCALAPPDATA%\mangania\cache`（未設定時は `%USERPROFILE%\AppData\Local\mangania\cache`、それも使えなければ OS の一時ディレクトリ）
  - macOS: `~/Library/Caches/mangania`
  - Linux: `$XDG_CACHE_HOME/mangania`（未設定時は `~/.cache/mangania`）
- 自動削除は行いません。不要になったらメニューの「ファイル」>「キャッシュを削除」で消してください。Linux ではネイティブメニューがないため、上記ディレクトリを手動で削除します。
- ファイル名は、解決済みの ZIP パス・ファイルサイズ・更新時刻・ZIP エントリ番号・エントリ名・CRC32・展開後サイズから作るハッシュです。画像形式の判定のため元の拡張子を残します。
- 展開はキャッシュディレクトリ内の一時ファイルへストリームし、完了後に原子的にリネームします。途中で残った一時ファイルも「キャッシュを削除」で消えます。
- キャッシュディレクトリを作れない、書き込めないなどの場合は、ページ読み込みエラーとして表示します。メモリへの読み替えは行いません。
- 壊れた、または切り詰められたキャッシュファイルは削除してエラーを表示します。次にそのページを開いたときに ZIP から再展開します。
- 画像フォルダのページは元ファイルを直接読むため、ディスクキャッシュの対象外です。読み込みに失敗しても元ファイルは削除しません。
- キャッシュには展開済みのページ画像が入り、手動で消すまで残ります。プライバシー上の理由で不要になった場合は、メニューまたは上記ディレクトリの削除で消してください。

## 表示中のページを保存

「ファイル」>「表示中のページを保存」、`Ctrl+S` / `Cmd+S`、または左ダブルクリックで、現在表示しているページを画像ファイルとして書き出します。

- 見開き・混合表示中でも **現在ページのみ** を保存します。
- ZIP 内の元画像バイト列をそのまま書き出すため、再エンコードによる画質劣化はありません。ZIP の展開済みディスクキャッシュ、または画像フォルダの元ファイルからコピーします。
- 拡張子は元画像のものを引き継ぎます。
- 出力先がなければ作成し、同名ファイルは上書きします。
- 保存結果はタイトルバーに表示されます。

## 設定ファイル

表示モード、保存設定、先読み、メモリキャッシュ、縮小フィルタ、拡大の可否はTOMLで設定します。

- macOS: `~/Library/Application Support/mangania/config.toml`
- Windows: `%APPDATA%\mangania\config.toml`
- Linux: `$XDG_CONFIG_HOME/mangania/config.toml`（未設定時は `~/.config/mangania/config.toml`）

`config.toml` は初回起動時に既定値で作成されます。コメント付きなので、そのまま編集して次回起動時に反映できます。

```toml
mode = "single"
export_dir = "~/Pictures/MangaNia"
export_name = "{book}_{page:03}"
prefetch = 2
cache_pages = 8
cache_mb = 256
decode_batch_size = 2
scale_filter = "triangle"
debug = false
allow_upscale = true
```

- `mode` は表示モードです。`single`（単ページ表示）、`spread`（見開き表示）、`mixed`（混合表示）のいずれかで、省略時は `single` です。以前の `spread = true/false` は使われません。
- `export_dir` は保存先ディレクトリです。`~` を展開します。省略時は `~/Pictures/MangaNia` です。
- `export_name` は保存ファイル名のテンプレートです。省略時は `{book}_{page:03}` です。
- `prefetch` は先読みする段数です（単ページ表示ではページ数、見開き・混合表示では2ページ単位）。省略時は 2 です。`--prefetch` を指定した場合は CLI が優先されます。
- `cache_pages` はメモリに保持するページ数です。省略時は 8、`0` は無制限です。各ページは表示サイズの画像を1枚だけ持ちます。
- `cache_mb` はメモリキャッシュの上限（MiB）です。省略時は 256、`0` は無制限です。`cache_pages` と `cache_mb` のどちらかに達した時点で、現在ページから遠い画像を破棄します。
- `decode_batch_size` は並列デコードするページ数です。省略時は 2、`0` は1ページずつ（直列）です。利用可能なコア数と上限8でクランプされます。増やすとフル解像度画像を同時に保持するため、メモリ使用量が増えます。
- `scale_filter` は縮小アルゴリズムです。`nearest` / `triangle` / `hamming` / `catmull_rom` / `mitchell` / `gaussian` / `lanczos3` のいずれかで、省略時は `triangle` です。不正な値は既定値に戻ります。
- `debug = true` にすると、`config.toml` と同じディレクトリの `debug.log` に読み込み・デコード・描画のログを出力します。通常は `false` のままにしてください。
- `allow_upscale` は画面より小さい画像を拡大するかどうかです。省略時は `true`（拡大する）です。`false` にすると縮小だけを行い、小さい画像は原寸で表示します。
- メモリキャッシュは表示サイズの画像のみを保持します。現在ページと見開き・混合表示の相手を優先し、`cache_pages` か `cache_mb` に達したら現在ページから遠いページの画像から破棄します。
- 拡張子はテンプレートに含めず、元画像から自動で付きます。
- 設定の読み込みに失敗した場合は警告を出して既定値を使い、不正な `config.toml` は上書きしません。メニューから設定を変更したときには設定全体を保存します。

### ファイル名テンプレート

| プレースホルダー | 内容 | 例 |
| --- | --- | --- |
| `{book}` | ZIP / フォルダ名（拡張子なし） | `book` |
| `{page}` | 1始まりのページ番号 | `7` |
| `{page:03}` | 3桁ゼロ埋めのページ番号 | `007` |
| `{page:000}` | `0` の数だけゼロ埋め | `007` |
| `{name}` | 元画像名（拡張子なし） | `001` |

未知のプレースホルダーはそのまま残ります。ファイル名に使えない文字やパス区切りは `_` に置換します。

## キーバインドとマウス設定

キー割り当てとマウス操作は `config.toml` とは別のファイルで設定します。初回起動時に既定値のファイルが作成されます。場所は `config.toml` と同じディレクトリです。

### keybindings.toml

```toml
[keys]
next = ["Right"]
prev = ["Left"]
first = ["Home"]
last = ["End"]
toggle_spread = ["v"]
single_page = []
spread_page = []
mixed_page = []
toggle_fullscreen = ["F11", "Enter"]
save_page = ["Ctrl+S", "Cmd+S"]
quit = ["Escape"]
```

| アクション | 内容 |
| --- | --- |
| `next` | 次の表示（見開きでは2ページ、混合表示では組に応じて1〜2ページ） |
| `prev` | 前の表示（見開きでは2ページ、混合表示では組に応じて1〜2ページ） |
| `next_single` | 1ページ進む（見開き・混合表示では開始ページを1つずらす） |
| `prev_single` | 1ページ戻る（見開き・混合表示では開始ページを1つずらす） |
| `first` | 先頭へ |
| `last` | 末尾へ |
| `toggle_spread` | 表示モードを順に切り替える（単ページ → 見開き → 混合） |
| `single_page` | 単ページ表示にする |
| `spread_page` | 見開き表示にする |
| `mixed_page` | 混合表示にする |
| `toggle_fullscreen` | 全画面の切替 |
| `save_page` | 表示中のページを保存 |
| `quit` | 終了（全画面中は全画面解除） |

- アクション名は上表の名前のみを使用します。以前の別名（`next_page`、`previous`、`fullscreen`、`save`、`exit` など）は認識されないため、上表の名前に変更してください。未知の名前は警告して無視します。
- 同じ入力が複数のアクションに割り当てられた場合、上表で先にあるアクションが優先されます。これは既定値と明示的な割り当ての間でも同じです。
- キーは `修飾キー+キー` で指定します。修飾キーは `Ctrl`、`Shift`、`Alt`、`Super`（macOS の Cmd）です。
- 名前付きキーは `Right`、`Left`、`Up`、`Down`、`Home`、`End`、`PageUp`、`PageDown`、`Escape`、`Space`、`Enter`、`Tab`、`Backspace`、`Delete`、`Insert`、`F1`〜`F35` などです。
- 1文字キーはそのまま書きます（`v`、`s`、`1`）。`+` は `plus`、または `Ctrl++` のように書けます。
- 1つのアクションに複数のキーを割り当てられます。`[]` にするとそのアクションを無効化できます。
- 修飾キーは完全一致です（`s` と `Shift+s` は別の割り当て）。
- ファイルに書かなかったアクションは既定値を使います。書いたアクションは既定値を置き換えます。
- 既存の `keybindings.toml` がある場合、その内容が優先されます。既定値に追加されたキー（例: `Enter`）を使うには、ファイルを編集するか削除して再生成してください。

### mouse.toml

```toml
wheel_threshold = 50.0
double_click_ms = 500

[bindings]
next = ["left", "wheel_down"]
prev = ["right", "wheel_up"]
next_single = ["middle"]
save_page = ["double_left"]
```

- ボタンは `left`、`right`、`middle`、`back`、`forward`、ホイールは `wheel_up`、`wheel_down` です。
- 中クリックは既定で `next_single` に割り当てられ、見開き・混合表示中でも1ページだけ進みます。
- ダブルクリックは `double_left`、`double_right`、`double_middle`、`double_back`、`double_forward` です。
- `wheel_threshold` は1ページ送りに必要なスクロール量です（既定 `50.0`）。
- `double_click_ms` はダブルクリックと判定する時間です（既定 `500`）。
- ダブルクリックが割り当てられたボタンでは、シングルクリックの動作を `double_click_ms` の間待ってから実行します。これにより、ダブルクリック時にシングルクリックの動作（ページ送りなど）が先に実行されません。
- アクション名は `keybindings.toml` と同じです。1つのアクションに複数指定でき、`[]` で無効化できます。
- 既存の `mouse.toml` の `double_click_ms` は自動で変更されません。既定値を変えるには `500` に編集するか、ファイルを削除して再生成してください。

## 全画面

- メニューの「表示」>「全画面表示」、または `F11` / `Enter` で切り替えます。
- 「全画面表示」メニューには現在の状態がチェックで表示されます。
- 全画面中は `Esc` で全画面を解除します。ウィンドウ表示中の `Esc` は終了です。
- ページ番号やエラーはタイトルバーに表示するため、全画面中は見えません。
- Windows の全画面ではメニューバーとマウスカーソルも隠れます。`F11` / `Enter` / `Esc` で戻れます。

## 対応形式

- ZIP / CBZ（Stored / Deflate）
- 画像フォルダ（選択したフォルダ直下の画像のみ。サブフォルダは対象外）
- JPEG（ベースライン / プログレッシブ）
- PNG
- WebP
- BMP

JPEG 2000 は対象外です。

## 設計上の特徴

- ZIP の Central Directory を索引化し、自然順に並べる（ページ保存時は再度開く）
- 画像フォルダは直下の画像だけを自然順に並べる。サブフォルダ、シンボリックリンク、隠しファイルは無視する
- 現在ページと見開き・混合表示の相手を先頭に、次ページ、その先の順で1本のキューに並べ、順読みを優先
- ZIP を開く処理、読み出し、画像デコード、ページ保存はバックグラウンドで行う
- デコードしたページはウィンドウに合わせた表示サイズへ縮小し、原寸画像は保持しない
- 表示サイズの画像を `cache_pages`（既定8ページ）と `cache_mb`（既定256MiB）の小さい方まで保持。1ページ1枚。現在ページと見開き・混合表示の相手を守り、現在ページから遠いものから破棄（同じ距離なら未来のページを優先）
- ZIP エントリは専用ディレクトリのディスクキャッシュへ展開し、そのファイルから直接デコード。展開済みバイト列はメモリに保持しない。画像フォルダは元ファイルを直接デコードする。最大 `decode_batch_size` ページをバッチにして並列デコードする
- ディスクキャッシュは自動削除せず、メニューの「キャッシュを削除」で手動削除。壊れた ZIP のキャッシュファイルは削除し、次回読み込み時に ZIP から再展開
- ページ移動ではキャッシュを維持し、ウィンドウサイズ・縮小フィルタ・表示モードの変更時は再デコード
- 縮小は `fast_image_resize` の SIMD 実装を使い、描画は行単位コピーで転送する
- 縮小フィルタ（nearest / triangle / hamming / catmull_rom / mitchell / gaussian / lanczos3）を設定・メニューから選択
- 画面に収まらないページだけ縮小し、小さい画像の拡大はメニューの「表示」>「拡大を許可」で切り替え
- 次ページの準備中は直前のフレームを保持して暗転を防ぐ
- 読み込み失敗時は直前のページを消し、タイトルバーにエラーを表示する
- 壊れた ZIP / 画像はエラーとして扱い、プロセスは落とさない
- RAR/CBR・7z・HTML は非対応、空・破損は壊れたファイルとしてエラーを表示
- パストラバーサル、隠しファイル、`__MACOSX`、シンボリックリンクを除外
- エントリサイズ・エントリ数に上限を設け、対応形式を限定する
- 単ページ表示 / 見開き表示 / 混合表示をメニューバーで切替
- 全画面表示（F11 / メニュー）
- 「移動」「表示」メニューからナビゲーション、表示モード、全画面、縮小フィルタ、拡大の可否を操作
- 設定項目はメニューバーに置き、専用の設定画面は持たない
- クリック・ホイール・キーでページ送り（割り当て変更可能）
- キーとマウスの割り当てを別々の TOML ファイルで設定
- 左ダブルクリックでページ保存。競合するシングルクリック動作だけを遅延
- UI は `winit` + `softbuffer`（D&D と CPU 描画のため）

## Windows 7 向けビルド

Windows 7 は Rust の Tier 3 ターゲットです。nightly と `build-std` が必要です。Release にも `windows7-x86_64` の zip を添付します。

```sh
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
cargo +nightly build -Z build-std --target x86_64-win7-windows-msvc --release
```

- 通常の `windows-x86_64` 版は Windows 10 以降向けです。Windows 7 ではこの手順か、Release の `windows7-x86_64` を使ってください。
- MSVC ツールチェーンと、Windows 7 側の Universal CRT 更新が必要です。
- `winit` は Windows 10 以降の DPI API を動的に読み込み、存在しない場合はフォールバックします。
- ネイティブメニューは OS の API を `src/platform/` で直接使用しています（Windows は Win32、macOS は AppKit）。
- **Windows 7 実機での検証は未実施です。** クリーンな Win7 SP1 x64 環境での起動確認が残っています。

## CI / リリース

- Pull Request と main への push で GitHub Actions の CI が走ります。
  - Pull Request: Ubuntu で `cargo fmt --check` / `cargo clippy --all-targets -- -D warnings` / `cargo test`、Windows で `cargo check --all-targets`
  - main: Ubuntu でテスト、Windows / macOS で `cargo check --all-targets`
  - OS 固有の実行テストは、GUI テスト基盤を整備してから追加します
  - 手動実行（`workflow_dispatch`）では Ubuntu / Windows / macOS の3環境を確認できます
- バージョンは `Cargo.toml` の `[package] version` で管理します。
- `version` を更新し、`cargo check` で `Cargo.lock` も更新して main にマージすると、`v<version>` タグと GitHub Release を作成します。
- Release には次の成果物を添付します。
  - `mangania-v<version>-windows-x86_64.zip`（Windows 10 以降）
  - `mangania-v<version>-windows7-x86_64.zip`（Windows 7）
  - `mangania-v<version>-macos-<arch>.tar.gz`
  - `mangania-v<version>-linux-x86_64.tar.gz`
- Release notes は前回タグからのコミットタイトル一覧です。
- Windows 10 以降向けは標準の `x86_64-pc-windows-msvc`、Windows 7 向けは nightly + `build-std` の `x86_64-win7-windows-msvc` でビルドします。

## 既知の制約

- 設定画面、閲覧位置の保存は未実装です。表示モード・縮小フィルタ・拡大の可否は「表示」、ページ移動は「移動」メニューから変更できます。
- ディスクキャッシュを削除しても、次にページを開くときに再展開されます。キャッシュ先に書き込めない環境ではページを表示できません。
- 読み方向は右→左固定で、表紙の単独表示はありません。
- ウィンドウサイズ、縮小フィルタ、表示モード、拡大の可否を変えると、表示サイズキャッシュを破棄して再デコードします。
- macOS でのみ実行確認済みです。Windows / Linux はコンパイル確認までです。
- Windows 7 はビルド手順とコードのみで、実機未検証です。
