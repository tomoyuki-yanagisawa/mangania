## やりたいこと

`.lnk` の解決（COM / `IShellLink`）を `src/archive.rs` から分離し、ZIP の読み込みと Windows 固有の入口処理を分ける。

## スコープ

- やること: `.lnk` 解決を `src/open.rs`（または `src/shortcut.rs`）へ移す
- やらないこと: ショートカット解決の仕様変更

## 受け入れ条件

- [x] `archive.rs` に COM / `IShellLink` のコードがない
- [x] `archive::Archive` は ZIP の読み込みに集中している
- [x] `.lnk` 解決と通常の ZIP 読み込みの既存テストが通る

## 実装メモ

- 関連ファイル: `src/archive.rs`、`src/app.rs`、`src/open.rs`（新規）
- 方針: `open.rs` に `resolve_shortcut` と Windows の COM 実装を移し、`Archive::open` の前段でパスを解決する
- `app.rs` / `headless.rs` / `export.rs` のどこで解決するかを揃え、二重解決を避ける
- 実装では `open::Entry::open` が解決済みパス・形式・`Archive` を返し、アプリは解決済みパスを保持する
- 形式判定（ZIP / RAR / 7z / HTML / 空 / 破損 / 不明）も `open.rs` に集約した

## 確認

## リスク / 依存

- 解決を呼ぶ場所が増えると、パス解決漏れや二重解決が起きる
- 非 Windows では `.lnk` を明確にエラーにする現在の挙動を維持する
