## やりたいこと

Windows 7 対応のため、Windows ビルドから `dirs` を外した。現在は Windows だけ `%APPDATA%` / `%USERPROFILE%` を直接読み、macOS / Linux は `dirs` を使う形になっており、パス解決の実装がプラットフォームごとに分かれている。クロスプラットフォームで保守しやすい方法を決め直す。

## スコープ

- やること: 設定・ホーム・ピクチャフォルダの解決方法の候補を比較し、方針を決める
- やらないこと: この項目内での実装完了（方針決定後に別項目で行う）

## 受け入れ条件

- [ ] Windows 7 で Win8 以降の API（`combase.dll` など）を要求しない
- [ ] macOS / Linux の既存の設定場所を維持する
- [ ] 採用方針を ADR に記録する

## 実装メモ

- 関連ファイル: `src/config.rs`、`Cargo.toml`、`docs/DECISIONS.md`
- 候補:
  - Windows は環境変数、macOS / Linux は `dirs`（現状）
  - 全 OS で自前のパス解決に統一する
  - exe と同じディレクトリに設定を置く（ポータブル運用。Program Files の書き込み権限に注意）
  - Windows の Known Folder API を自前で呼ぶ（`windows-sys` 0.52 は `ole32.dll` にリンクされる）

## 確認

- [ ] `cargo test`
- [ ] `cargo clippy --all-targets`
- [ ] 手動確認: Windows 7 / macOS / Linux で設定ファイルの場所
- [ ] 必要なドキュメント更新

## リスク / 依存

- exe 隣に置く案は、Program Files 配下では書き込みできない
- 設定が exe ごとに分散し、アップデート時に引き継ぎが必要になる
- Roaming / ローカル設定のどちらに置くかを決める必要がある
