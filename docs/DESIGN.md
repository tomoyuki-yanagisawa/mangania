# MangaNia 設計

更新日: 2026-11-19
対象: Phase 1 PoC（実装済み）

## 1. 目的

ZIP 内の漫画画像を高速に読むための、小さなネイティブビューアです。次の体験を重視します。

- ZIP を開いてすぐ読める
- 次のページがすぐ表示される
- メモリ使用量を制御できる
- Windows 7 を優先しつつ、macOS / Linux でも動く
- GPU を必須にしない

## 2. 非目標

画像編集、動画、ネットワーク同期、サーバー、GPU 専用レンダラ、RAR / 7z、独自 ZIP 実装、プラグイン体系、大規模な書庫管理機能は対象外です。

## 3. プラットフォーム

- Windows 7 SP1 x64 を優先します。コードとビルド手順は用意していますが、実機検証は未実施です。
- macOS（Apple Silicon）と Linux x86_64 でもビルドできます。
- ネイティブメニューは Windows / macOS のみです。Linux ではキーバインドで操作します。
- 描画は CPU のピクセルバッファを使い、GPU を必須にしません。

## 4. アーキテクチャ

### データフロー

```text
ZIP ファイル / 画像フォルダ
  ↓ ZIP はバックグラウンドで Central Directory を索引化、フォルダは直下の画像を列挙
自然順のページ一覧（ZIP エントリ番号 / ファイル名）
  ↓ 現在ページを最優先で要求
ワーカースレッド: ZIP エントリはディスクキャッシュへストリーム展開、フォルダは元ファイルを参照
  ↓ キャッシュファイル / 元ファイルから直接デコード
ImageReady
  ↓
UI スレッド: ウィンドウに合わせた表示サイズへ縮小 → 原寸画像を破棄
  ↓
Viewer の表示サイズキャッシュ（現在ページ＋先読み）
  ↓
render::image::render_pages
  ↓
softbuffer のピクセルバッファ
```

## 5. アーカイブとページモデル

- `archive::open::Entry::open` が Windows ショートカットを解決し、形式を判定してから ZIP または画像フォルダを開きます。
- `zip` crate で ZIP / CBZ を読みます。Stored / Deflate に対応し、RAR / 7z は検出して明示的なエラーにします。
- `Archive` は ZIP の Central Directory、または画像フォルダ直下の索引化を担当し、画像を自然順に並べます。
- 画像フォルダは選択したフォルダ直下の画像だけを対象にします。サブフォルダは無視し、自動で1段下がることはしません。サブフォルダを読むときは、そのフォルダを開き直します。
- `Entry` は解決済みのパスを保持するため、アプリは保存時に同じパスを再利用できます。
- ZIP ではパストラバーサル、隠しファイル、`__MACOSX`、対応外拡張子を除外します。画像フォルダではシンボリックリンク、隠しファイル、サブディレクトリ、対応外拡張子を除外します。
- エントリ数と展開後サイズに上限を設け、壊れた ZIP でもプロセスを落とさない方針です。
- ページは ZIP エントリ番号、またはフォルダ内のファイル名への参照として保持します。`Viewer` はページ数と現在位置を管理し、保存時は元の ZIP またはフォルダを開き直して元画像を取得します。
- 先頭に自己解凍用などのデータがある ZIP は、先頭バイトだけで拒否せず `zip` crate の判定に任せます。

## 6. 先読みとキャッシュ

- ZIP 読み出しと画像デコードは専用ワーカースレッドで行い、UI スレッドをブロックしません。
- ZIP を開く処理とページ保存もバックグラウンドで実行します。連続して開いた場合、古い要求の結果は破棄します。
- 現在ページと表示相手は1つのバッチとしてキュー先頭に割り込み、未着手の先読みジョブを破棄します。2ページを別々に要求すると後の要求が前の要求を捨てるため、まとめて積みます。
- 先読みは現在ページより後ろだけを対象にします。単ページ表示では `prefetch` ページ、見開き表示と混合表示では `prefetch` 段（2ページ単位）を対象にします。
- ワーカーは結果を bounded channel で返し、UI に `ImageReady` イベントを送ります。
- ワーカーは ZIP エントリをディスクキャッシュへストリーム展開し、そのファイルを `image::ImageReader` で直接デコードします。展開済みバイト列を `Vec` に保持しません。画像フォルダのページはディスクキャッシュを使わず、元ファイルを直接デコードします。
- キャッシュ先は OS ごとの専用ディレクトリです。Windows は `%LOCALAPPDATA%\mangania\cache`（未設定時は `%USERPROFILE%\AppData\Local\mangania\cache`、それも使えなければ OS の一時ディレクトリ）、macOS は `~/Library/Caches/mangania`、Linux は `$XDG_CACHE_HOME/mangania`（未設定時は `~/.cache/mangania`）です。
- キャッシュキーは、解決済み ZIP パス、ZIP のファイルサイズと更新時刻、ZIP エントリ番号、エントリ名、CRC32、展開後サイズです。ハッシュをファイル名にし、画像形式判定のため元の拡張子を残します。ハッシュはツールチェーン更新で変わってよく、その場合はキャッシュが再生成されます。
- キャッシュは自動削除しません。不要になったらメニューの「キャッシュを削除」で手動削除します。途中で残った一時ファイルも同じ操作で消えます。
- ミス時はキャッシュディレクトリ内の一時ファイルへストリームし、完了後に原子的にリネームします。
- ディスクキャッシュは ZIP ページ読み込みの唯一の経路です。ディレクトリを作れない、書き込めない、読めない場合はページエラーとして扱い、メモリ読み出しへは切り替えません。
- デコードに失敗したキャッシュファイルは削除してエラーにします。次にそのページを読むときに ZIP から再展開します。画像フォルダの元ファイルは削除しません。
- ワーカーが返すのはデコード済みの原寸画像です。UI スレッドは受け取った直後に現在のウィンドウへフィットする表示サイズへ縮小し、表示サイズキャッシュへ入れて原寸画像を破棄します。原寸画像は保持しません。
- 表示画像はページごとに1枚だけ作り、原寸画像は破棄します。表示サイズは単ページ表示ならウィンドウ全体、見開き表示なら左右半分のセルです。混合表示ではページ自身の向きで決め、縦長は左右半分、横長と正方形はウィンドウ全体にフィットさせます。隣のページとの組み合わせではサイズを変えないため、ペアが変わっても再縮小しません。
- フィットは縦横比を保ち、はみ出すページを縮小します。`allow_upscale = false` のときは倍率を 1.0 で頭打ちにし、画面より小さいページを原寸のまま中央に置きます。既定は `true` です。
- ページの向きはデコード時に記録し、キャッシュを破棄しても保持します。混合表示では、現在ページが横長なら単ページ、縦長なら右セルに表示し、次ページも縦長なら左セルに並べます。次ページが横長・正方形・末尾なら左セルは空白です。
- キャッシュキーはページのみです。表示サイズ・縮小フィルタ・表示モード・拡大の可否が変わるとキャッシュを破棄するため、サイズやフィルタをキーに含める必要はありません。
- 表示サイズキャッシュは `cache_pages`（既定8ページ、1ページ1枚）と `cache_mb`（既定128MiB）をソフト上限として保持します。1つ前・現在・1つ先の表示に必要なページは、上限を超えても残します。
- 上限を超えたときは、まず1つ前の表示より過去のページを、遠いものから破棄します。次に1つ先の表示より未来のページを遠い順に破棄します。前後1表示と現在のページは破棄しません。同じ距離なら古い挿入を先に破棄します。
- `prefetch`、`cache_pages`、`cache_mb` は `config.toml` で変更できます。`--prefetch` は設定を上書きします。
- ページ移動ではキャッシュをクリアしません。近いページの表示画像を再利用し、新しい挿入は移動後の現在ページを基準に距離を計算します。
- キャッシュから破棄されたページは、現在位置に応じて再び先読みの対象になります。
- ウィンドウサイズ、縮小フィルタ、表示モード、拡大の可否が変わるとキャッシュをクリアし、現在ページと表示相手を再要求します。この場合は再デコードが発生します。ページの向きの記録は保持します。
- 縮小は `fast_image_resize` の SIMD 実装を使います。RGBA8 と非ゼロの表示サイズだけを扱うため、縮小処理は失敗しない前提です。フィルタは nearest / bilinear（triangle）/ hamming / catmull_rom / mitchell / gaussian / lanczos3 に対応します。

## 7. 描画

- ワーカーから届くデコード結果は `RgbaImage` です。UI 側で表示サイズへ縮小し、原寸は保持しません。
- `render::image::render_pages` は、単ページならウィンドウ中央、見開きなら左右半分のセルに画像を置き、0RGB の `u32` バッファへ行単位でコピーします。左セルは右端（中央）寄せ、右セルは左端（中央）寄せで、ページがないセルは空白になります。混合表示で縦長ページの次が横長・末尾のときも、右セルだけに描画します。縮小はデコード結果を受け取ったときの1回だけです。
- 背景色は `0x202020` です。
- 見開きでは左ページを先に、右ページを次に描画します（配置は右→左）。
- 次ページの準備中は直前のフレームを保持し、暗転を防ぎます。
- 先読みで届いたページが現在の表示を変えない場合は再描画しません。同じ内容を再提示すると、環境によってちらつきの原因になるためです。
- 現在ページの読み込み失敗時は直前のフレームを消し、エラーをタイトルバーに表示します。

## 8. 入力

- `input::bindings::Action` をメニュー・キーボード・マウスで共有します。
- キー割り当ては `keybindings.toml`、マウス割り当ては `mouse.toml` で変更できます。
- `next_single` / `prev_single` は1ページ単位で移動します。見開き・混合表示中は開始ページを1つずらします。`next` / `prev` とあわせて「移動」メニューから実行できます。
- `next` / `prev` は表示単位で移動します。混合表示では、現在ページが縦長で次ページも縦長なら2ページ、それ以外は1ページ進みます。戻るときは、直前の2ページがともに縦長なら2ページ、それ以外は1ページ戻ります。途中へジャンプした後は、順読み時と組がずれる場合があります。
- 中クリックは既定で `next_single` に割り当てています。
- 修飾キーは完全一致で判定します。文字キーは大文字小文字を区別しません。
- ダブルクリックはボタン・時間・カーソル位置で判定します。ダブルクリックが割り当てられたボタンだけ、シングルクリック動作を `double_click_ms` の間だけ遅延させます。
- ウィンドウが非アクティブなときのクリックは操作に使いません。Windows では `WM_MOUSEACTIVATE` を処理して、クライアント領域のアクティブ化クリックを OS 側で破棄します。その他の環境では `Window::has_focus()` で非アクティブ時のクリックを無視します。
- ホイールは移動量を蓄積し、`wheel_threshold` を超えたらページ送りなどのアクションを実行します。

## 9. 設定

設定は OS 標準の設定ディレクトリに置きます。

| ファイル | 内容 |
| --- | --- |
| `config.toml` | 表示モード、保存先、保存ファイル名、先読み数、メモリキャッシュのページ数と上限、縮小フィルタ、小さい画像の拡大可否 |
| `keybindings.toml` | キー割り当て |
| `mouse.toml` | マウス・ホイール割り当て |

- `config.toml`、`keybindings.toml`、`mouse.toml` は初回起動時に既定値で作成します。
- `config.toml` はコメント付きで生成し、設定画面の代わりに直接編集できるようにします。
- 設定は可能な限りメニューから変更できるようにし、`config.toml` を永続データとして使います。表示モード・縮小フィルタ・拡大の可否は「表示」メニューから変更でき、そのときに設定全体を保存します。
- 読み込みに失敗した場合は既定値へフォールバックし、stderr に警告を出します。
- 既定値と UX の詳細は [PREFERENCES.md](PREFERENCES.md) を参照してください。

## 10. 表示中ページの保存

- 現在ページのみを保存します。見開き中でも 1 ページだけです。
- ZIP 内の元画像バイト列、または画像フォルダの元ファイルをそのまま書き出し、再エンコードしません。ZIP の展開済みディスクキャッシュがある場合は、そのファイルからコピーします。
- 拡張子は元画像から引き継ぎます。
- 出力先がなければ作成し、同名ファイルは上書きします。
- ファイル名は `{book}` / `{page}` / `{page:03}` / `{name}` などのプレースホルダーで指定できます。
- パス区切りや OS で使えない文字は `_` に置換します。

## 11. UI

- ネイティブメニューは「ファイル」「移動」「表示」で構成します。
- 「移動」にはページ移動（次のページ、前のページ、1ページ進む、1ページ戻る、先頭へ、末尾へ）を置きます。
- 「表示」には表示モード、縮小フィルタ、拡大を許可、全画面を置きます。
- 「単ページ表示」「見開き表示」「混合表示」「全画面表示」はチェック状態を現在のモードに同期します。
- 「表示」>「縮小フィルタ」に各フィルタを並べ、現在の設定だけをチェックします。「表示」>「拡大を許可」はチェック可能な項目で、`allow_upscale` と同期します。選択時は設定を保存し、縮小キャッシュと直前フレームを破棄して再描画します。
- タイトルバーにファイル名、ページ番号、読み込み状態、エラー、保存結果を表示します。
- 全画面はボーダーレスで、`Esc` は全画面中なら解除、通常ウィンドウなら終了です。
- Windows の全画面ではネイティブメニューバーとマウスカーソルを隠し、解除時に元のメニューバーを復元します。
- Linux にはネイティブメニューがないため、既定のキーバインドで操作します。

## 12. CLI / ヘッドレス

GUI を開かずに確認できる手段を用意しています。

- `--list`: 自然順のページ一覧を表示
- `--check`: 全ページをデコードしてエラーを報告
- `--render-page PAGE OUTPUT`: 指定ページを画像として保存
- `--prefetch N`: 先読みする段数（単ページ表示ではページ数、見開き・混合表示では2ページ単位。`config.toml` の `prefetch` を上書き）
- `--help`: 使い方

## 14. 既知の制約と今後

- RAR / 7z、JPEG 2000、JPEG XL、AVIF は未対応です。
- 画像フォルダは直下の画像だけを対象にし、サブフォルダは自動で読みません。シンボリックリンクも対象外です。
- 設定画面、閲覧位置の保存は未実装です。表示モード・縮小フィルタ・拡大の可否は「表示」、ページ移動は「移動」メニューから変更できます。
- ZIP をディスクキャッシュへ書き込めない環境ではページを表示できません。
- 読み方向は右→左固定で、表紙を単独表示する設定はありません。混合表示で横長ページを単独表示するのはページの向きによるものです。
- ウィンドウサイズ、縮小フィルタ、表示モード、拡大の可否を変えると、表示サイズキャッシュを破棄して再デコードします。
- Windows 7 は実機未検証、Windows / Linux はコンパイル確認までです。
- 今後の候補: 設定画面、閲覧位置保存、表紙単独表示、画像形式の拡張、ベンチマーク自動化。
