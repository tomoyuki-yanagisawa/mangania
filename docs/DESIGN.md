# MangaNia 設計

更新日: 2026-11-12
対象: Phase 1 PoC（実装済み）

## 1. 目的

ZIP 内の漫画画像を高速に読むための、小さなネイティブビューアです。次の体験を重視します。

- ZIP を開いてすぐ読める
- 次のページがすぐ表示される
- メモリ使用量を制御できる
- Windows 7 を優先しつつ、macOS / Linux でも動く
- GPU を必須にしない

## 2. 非目標

画像編集、動画、ネットワーク同期、サーバー、GPU 専用レンダラ、RAR / 7z、独自 ZIP 実装、プラグイン体系、大規模な書庫管理機能は対象外です。

## 3. プラットフォーム

- Windows 7 SP1 x64 を優先します。コードとビルド手順は用意していますが、実機検証は未実施です。
- macOS（Apple Silicon）と Linux x86_64 でもビルドできます。
- ネイティブメニューは Windows / macOS のみです。Linux ではキーバインドで操作します。
- 描画は CPU のピクセルバッファを使い、GPU を必須にしません。

## 4. アーキテクチャ

### モジュール

| モジュール | 責務 |
| --- | --- |
| `main.rs` | CLI の入口 |
| `cli.rs` | 引数解析 |
| `app.rs` | winit イベントループ、ウィンドウ、アクション実行、描画 |
| `click.rs` | シングル / ダブルクリックの判定と保留状態 |
| `viewer.rs` | 現在ページ、ページ一覧、キャッシュ、先読み要求 |
| `cache.rs` | ページ数・バイト予算付きのデコード済み画像キャッシュ |
| `navigation.rs` | ページ移動の純粋関数 |
| `archive.rs` | ZIP 索引、自然順、安全なエントリ読み出し |
| `decoder.rs` | JPEG / PNG / WebP のデコード |
| `prefetch.rs` | ワーカースレッド、優先度付きジョブ、通知 |
| `view.rs` | フィット・見開き配置・0RGB バッファへの描画 |
| `config.rs` | 一般設定の TOML 読み書き |
| `bindings/` | アクション定義、キー・マウス割り当ての TOML 読み書き |
| `export.rs` | 表示中ページの保存、ファイル名テンプレート |
| `menu.rs` | Windows / macOS のネイティブメニュー |
| `headless.rs` | GUI なしの `--list` / `--check` / `--render-page` |
| `event.rs` | ワーカー / メニューから UI へのイベント |

### データフロー

```text
ZIP ファイル
  ↓ Central Directory を一度だけ索引化
自然順のページ一覧（ZIP エントリ番号）
  ↓ 現在ページを最優先で要求
ワーカースレッド: エントリ読み出し → 画像デコード
  ↓
Viewer のキャッシュ（現在ページ＋先読み）
  ↓
view::render_pages
  ↓
softbuffer のピクセルバッファ
```

## 5. ZIP とページモデル

- `zip` crate で ZIP / CBZ を読みます。Stored / Deflate に対応し、RAR / 7z は対象外です。
- `Archive::open` で Central Directory を一度だけ索引化し、画像エントリを自然順に並べます。
- パストラバーサル、隠しファイル、`__MACOSX`、対応外拡張子を除外します。
- エントリ数と展開後サイズに上限を設け、壊れた ZIP でもプロセスを落とさない方針です。
- ページは ZIP エントリ番号の配列として保持します。`Viewer` はページ数と現在位置を管理し、保存時は元 ZIP を開き直して元画像バイト列を取得します。

## 6. 先読みとキャッシュ

- ZIP 読み出しと画像デコードは専用ワーカースレッドで行い、UI スレッドをブロックしません。
- 現在ページの要求はキュー先頭に割り込み、未着手の先読みジョブを破棄します。
- ワーカーは結果を bounded channel で返し、UI に `ImageReady` イベントを送ります。
- キャッシュは `先読み枚数 + 2` ページ、かつ最大 128MiB を上限にします。現在ページは常に保持します。
- バイト上限を超える先読み画像は破棄します。ディスクキャッシュは使いません。

## 7. 描画

- デコード結果は `RgbaImage` です。
- `view::render_pages` が単ページ・見開きを同じスケール計算でフィットし、0RGB の `u32` バッファへ描画します。
- 背景色は `0x202020` です。
- 見開きでは左ページを先に、右ページを次に描画します（配置は右→左）。
- 次ページの準備中は直前のフレームを保持し、暗転を防ぎます。

## 8. 入力

- `bindings::Action` をメニュー・キーボード・マウスで共有します。
- キー割り当ては `keybindings.toml`、マウス割り当ては `mouse.toml` で変更できます。
- 修飾キーは完全一致で判定します。文字キーは大文字小文字を区別しません。
- ダブルクリックはボタン・時間・カーソル位置で判定します。ダブルクリックが割り当てられたボタンだけ、シングルクリック動作を `double_click_ms` の間だけ遅延させます。
- ホイールは移動量を蓄積し、`wheel_threshold` を超えたらページ送りなどのアクションを実行します。

## 9. 設定

設定は OS 標準の設定ディレクトリに置きます。

| ファイル | 内容 |
| --- | --- |
| `config.toml` | 表示モード、保存先、保存ファイル名 |
| `keybindings.toml` | キー割り当て |
| `mouse.toml` | マウス・ホイール割り当て |

- `keybindings.toml` と `mouse.toml` は初回起動時に既定値で作成します。
- `config.toml` は設定を保存したときに作成します。
- 読み込みに失敗した場合は既定値へフォールバックし、stderr に警告を出します。
- 既定値と UX の詳細は [PREFERENCES.md](PREFERENCES.md) を参照してください。

## 10. 表示中ページの保存

- 現在ページのみを保存します。見開き中でも 1 ページだけです。
- ZIP 内の元画像バイト列をそのまま書き出し、再エンコードしません。
- 拡張子は元画像から引き継ぎます。
- 出力先がなければ作成し、同名ファイルは上書きします。
- ファイル名は `{book}` / `{page}` / `{page:03}` / `{name}` などのプレースホルダーで指定できます。
- パス区切りや OS で使えない文字は `_` に置換します。

## 11. UI

- ネイティブメニューは「ファイル」「移動」「表示」で構成します。
- 「1ページ表示」「見開き表示」「全画面表示」はチェック状態を現在のモードに同期します。
- タイトルバーにファイル名、ページ番号、読み込み状態、エラー、保存結果を表示します。
- 全画面はボーダーレスで、`Esc` は全画面中なら解除、通常ウィンドウなら終了です。
- Linux にはネイティブメニューがないため、既定のキーバインドで操作します。

## 12. CLI / ヘッドレス

GUI を開かずに確認できる手段を用意しています。

- `--list`: 自然順のページ一覧を表示
- `--check`: 全ページをデコードしてエラーを報告
- `--render-page PAGE OUTPUT`: 指定ページを画像として保存
- `--prefetch N`: 先読み枚数
- `--help`: 使い方

## 13. テスト

- `cargo test` で自然順、パス除外、画像デコード、描画、CLI、ヘッドレス、キャッシュ、ナビゲーション、先読み、設定 TOML、ページ保存、キー・マウス割り当て、クリック判定を検証します。
- `cargo clippy --all-targets` を品質ゲートにします。
- GUI の見た目とマウス操作は手動確認です。

## 14. 既知の制約と今後

- RAR / 7z、JPEG 2000、JPEG XL、AVIF は未対応です。
- 設定画面、ディスクキャッシュ、閲覧位置の保存は未実装です。
- 読み方向は右→左固定で、表紙を単独表示する設定はありません。
- Windows 7 は実機未検証、Windows / Linux はコンパイル確認までです。
- 今後の候補: 設定画面、閲覧位置保存、表紙単独表示、画像形式の拡張、ベンチマーク自動化。
