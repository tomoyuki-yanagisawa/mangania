# Win7 ターゲットでも `dirs` が `combase.dll` を要求する

| 項目 | 内容 |
| --- | --- |
| ID | 002 |
| Area | Windows 7 / 依存関係 |
| Updated | 2026-11-15 |

対象: `x86_64-win7-windows-msvc`、`dirs 7.0.0`。

## 症状

Win7 ターゲットでビルドした exe を起動すると、次のエラーになる。

```text
コンピュータに combase.dll がないため、プログラムを開始できません。
```

## 原因

`dirs 7.0.0` → `dirs-sys 0.5.0` → `windows-sys 0.61.2` の依存で、`CoTaskMemFree` が `combase.dll` にリンクされる。`combase.dll` は Windows 8 以降のもので、Windows 7 にはない。Win7 では同じ関数が `ole32.dll` にある。

PE のインポートを見ると、`combase.dll` の `CoTaskMemFree` だけが該当していた。

```python
import pefile

pe = pefile.PE("mangania.exe")
for entry in pe.DIRECTORY_ENTRY_IMPORT:
    print(entry.dll.decode(), [i.name for i in entry.imports])
```

## 対応

Windows ビルドでは `dirs` を使わず、`USERPROFILE` / `APPDATA` から設定・ホーム・ピクチャのパスを解決する。macOS / Linux は従来どおり `dirs` を使う。`dirs` を Windows の依存から外すことで、`dirs-sys` と `combase.dll` の import が消える。
